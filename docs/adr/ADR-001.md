# ADR-001: Use SQLite for Data Storage
### Context
Why did I choose this?
- The Dear Wishlist application lets users add items and edit/interact with them. The items the user adds needs to still be there even after the app stops running.
Each item stores information such as the item name, price, store, category, priority, and whether the item has been bought.The app needs a way to save information so that the wishlist items are not lost when the application is closed or reset. I needed to choose a storage method that happens to work with Flask and Python while being for a smaller application.

### Decision

The use of SQLite was decided as the database for Dear Wishlit.
SQLite will store the wishlist items in a table and allow the app to save and retrieve the user's data. SQLite works well with python and provides a structures way to manage the wishlist data without requiring a separate database server.


### Alternatives
1) JSON
- JSON file was considered to be an alternative to SQLite. I considered storing the wishlist items in a JSON file. JSON would have been
simple to set up, and the data would be easy to read directly from the file.I did not choose JSON because updating and managing individual wishlist items
could become harder as the application grows. SQLite provides a more
structured way to store, search, and update the data.
2) CSV File
- Another alternative I considered was storing the wishlist items in a CSV file.
The CSV file would be simple to create and could store each wishlist item as a
row with information such as the name, price, store, category, priority, and
bought status. I did not choose CSV because it is less convenient for updating, deleting,
and searching individual items. Since Dear Wishlist needs to perform these
actions regularly, I chose SQLite because it provides a more structured way
to manage the data.

### Consequences 
The consequences of using SQLite adds more complexity to the application. I have to
manage a database table and use database queries to work with the wishlist
items. If I change the information stored for each item later, I need to also
need to update the database structure. Another consequence would that if SQLite were to be created into a bigger application, it may not be able to hold all the information.
